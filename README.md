# ShopMates — семеен списък за пазаруване

Самостоятелно уеб приложение за общ семеен списък. React интерфейсът се сервира от собствен Node.js API, а данните се пазят в PostgreSQL. Потребителите в едно семейство могат едновременно да добавят продукти и да променят статуса им; актуализациите се изпращат към отворените браузъри чрез Server-Sent Events. Текущият вариант е за една инстанция на приложението; базата остава основният източник на данни, а браузърите презареждат периодично и при прекъсване на връзката.

Приложението не изисква Supabase или външен доставчик. Docker Compose стартира API/UI и PostgreSQL, като базата се съхранява в постоянен Docker volume.

## Възможности

- Регистрация и вход с имейл и парола.
- Семейни списъци с произволен брой членове; поканите са еднократни и изтичат след 7 дни.
- Добавяне, редактиране, маркиране като закупено и изтриване на продукти.
- Синхронизация на промените между устройствата, с периодично презареждане като резервен механизъм.
- Административен панел за потребители, роли, деактивиране и издаване на временна парола.
- Администраторска SQL конзола за директна поддръжка на базата. Променящите заявки изискват потвърждение в интерфейса; изпълняват се с ограничен срок и правата на отделен PostgreSQL потребител без superuser достъп.
- Изолирана Docker мрежа и постоянен том за PostgreSQL.

## Стартиране с Docker

Необходими са Docker Engine и Docker Compose v2.

1. Създайте конфигурация:

   ```powershell
   Copy-Item .env.example .env
   ```

2. В `.env` задайте собствени стойности за `POSTGRES_SUPERUSER_PASSWORD`, `DB_APP_PASSWORD`, `ADMIN_EMAIL` и `ADMIN_PASSWORD`. Администраторската начална парола трябва да е поне 12 символа. Използвайте случайни пароли с URL-безопасни символи за връзката към базата. Не качвайте `.env` в Git и не използвайте примерните стойности.
3. Стартирайте пакет:

   ```powershell
   docker compose up --build -d
   docker compose ps
   ```

4. Отворете `http://<IP-на-сървъра>:8080` (или локално `http://localhost:8080`). Може да промените външния адрес и порт с `APP_BIND_ADDRESS` и `APP_PORT` в `.env`.
5. Влезте с `ADMIN_EMAIL` и `ADMIN_PASSWORD`. Администраторският профил се създава при първо стартиране на празна база. След това се регистрирайте с обикновен профил и създайте семеен списък или използвайте покана.

**Важно за домашна мрежа:** примерната конфигурация използва HTTP и `COOKIE_SECURE=false`, за да работи на локален IP без сертификат. Използвайте я само в доверена LAN мрежа. HTTP не криптира паролите при пренос. Ако услугата ще е достъпна извън дома или през интернет, поставете я зад HTTPS reverse proxy, задайте `COOKIE_SECURE=true`, настройте `TRUST_PROXY=1` за един proxy hop и запазвайте host/protocol заглавките. Ограничете `APP_BIND_ADDRESS`/firewall така, че портът на приложението да е достъпен само от proxy; не публикувайте порта на PostgreSQL — той не е изложен от Compose.

## Backup и възстановяване

Базата е в Docker volume `postgres_data`; спирането или обновяването на контейнера не изтрива този volume.

Създаване на backup от PowerShell:

```powershell
New-Item -ItemType Directory -Force .\backups | Out-Null
docker compose exec -T db pg_dump --clean --if-exists -U postgres -d shopping -f /tmp/shopping-backup.sql
docker compose cp db:/tmp/shopping-backup.sql .\backups\shopping-backup.sql
docker compose exec -T db rm /tmp/shopping-backup.sql
```

При различно `POSTGRES_DB` сменете името в командата. Backup-ът съдържа лични данни и хешове на паролите — съхранявайте го защитено и не го комитвайте.

Възстановяването **изтрива и заменя** таблиците в базата. Копирайте файла в контейнера и го приложете само след като сте проверили, че това е правилният backup:

```powershell
docker compose cp .\backups\shopping-backup.sql db:/tmp/shopping-backup.sql
docker compose exec -T db psql -v ON_ERROR_STOP=1 -U postgres -d shopping -f /tmp/shopping-backup.sql
docker compose exec -T db rm /tmp/shopping-backup.sql
```

При различно `POSTGRES_DB` сменете името и при възстановяване. За пълно нулиране, включително изтриване на всички данни, командата `docker compose down -v` премахва постоянния volume и е необратима.

## Разработка без Docker

Локалната разработка изисква Node.js 20.19+ или 22.12+ и PostgreSQL. Създайте `.env` от `.env.example`, задайте администраторските данни и създайте локална роля и празна база, съответстващи на `DATABASE_URL`:

```sql
CREATE ROLE shopping_app LOGIN PASSWORD 'replace-with-another-long-random-password';
CREATE DATABASE shopping OWNER shopping_app;
```

Изпълнете SQL командите като PostgreSQL администратор и сменете примерната парола със стойността от `.env`. След това:

```powershell
npm install
npm run dev
```

Vite работи на `http://localhost:5173`, а заявките `/api` се препращат към Node.js API на порт `3000`. Сървърът създава схемата при стартиране.

Полезни команди:

```powershell
npm test
npm run typecheck
npm run build
```

## Бележки за администриране

- Ролята `admin` се задава за профила от `ADMIN_EMAIL` при стартиране. Началната парола се използва само при създаване на профила; последващи промени в `.env` не презаписват вече съществуваща парола.
- Администраторското нулиране генерира временна парола, прекратява съществуващите сесии и изисква потребителят да зададе нова парола при следващ вход.
- SQL конзолата е мощен инструмент: може да променя или изтрие данни и таблици. Използвайте я само с администраторски профил и след backup. Приложението изпълнява заявките с PostgreSQL роля, която не е superuser.
- Регистрацията е отворена за потребители, които имат достъп до приложението. За домашна употреба ограничете достъпа до мрежата си. За публично разполагане са необходими HTTPS, защита от злоупотреба при регистрация и процес за възстановяване на парола чрез имейл.
